# 01. 시나리오: 가상 고객사와 문제 정의

> FDE 업무의 시작은 코드가 아니라 "고객이 진짜 원하는 게 뭔지"를 파악하는 것이다.
> 이 문서는 고객사 첫 미팅 후 FDE가 정리하는 "문제 정의 메모"에 해당한다.

## 고객사 프로필

| 항목 | 내용 |
|---|---|
| 회사명 | 한빛산업 (가상) |
| 업종 | 산업용 기계 부품 유통 (중견기업, 직원 약 250명) |
| 담당 부서 | 구매팀 (6명) |
| 의사결정자 | 구매팀장 (예산 승인), 경영지원본부장 (최종 승인) |
| 실무 담당자 | 구매팀 대리 2명 (실제 사용자) |
| IT 환경 | 자체 ERP(더존), 이메일은 Google Workspace, 사내 개발 인력 없음 |

## 고객이 처음 말한 요청 (원문 그대로)

> "협력사에서 오는 견적서를 ERP에 일일이 손으로 입력하는데, 이걸 AI로 자동화할 수 없나요?"

## 발굴한 실제 상황 (첫 미팅에서 파악)

- 협력사 약 80곳에서 월 300~500건의 견적서가 **이메일 첨부 PDF**로 들어온다.
- 협력사마다 양식이 제각각이다. 엑셀로 만든 것, 워드로 만든 것, 스캔본도 일부 있다.
- 구매팀 대리 2명이 번갈아 가며 ERP에 수기 입력한다. **주당 약 2인일**이 소요된다.
- 수기 입력 과정에서 **월 10건 안팎의 오타/누락**이 발생하고, 이게 발주 오류로 이어진 적이 있다.
- 입력하는 필드: 공급사 정보, 견적일자, 유효기간, 품목(품명/규격/수량/단가/금액), 공급가액, 세액, 합계.
- ERP는 CSV 업로드 기능이 있다. 직접 API 연동은 ERP 벤더 협의가 필요해서 이번 범위에서는 어렵다.

## 진짜 문제 (고객의 요청 뒤에 있는 것)

고객은 "자동 입력"을 말했지만, 실제 고통은 두 가지다.

1. **시간**: 단순 반복 입력에 숙련 인력의 시간이 소모된다.
2. **신뢰**: 오타가 발주 사고로 이어지므로, 자동화해도 **사람이 최종 확인하는 절차**는 유지하고 싶어 한다.

따라서 "완전 자동화"가 아니라 **"AI가 초안을 뽑고, 사람이 빠르게 검토·확정하는 구조"**가 맞다.
이 판단이 이 프로젝트의 핵심 설계 결정이다.

## 성공 기준 (고객과 합의)

| 지표 | 현재 | 목표 |
|---|---|---|
| 건당 처리 시간 | 약 5분 (수기 입력) | 1분 이내 (검토 포함) |
| 필드 추출 정확도 | - | 95% 이상 (품목 라인 포함) |
| 입력 오류로 인한 발주 사고 | 월 1~2건 | 0건 |
| 검토자가 수정하는 필드 비율 | - | 측정 후 지속 감소 |

## 범위

**이번 범위 (Phase 1)**
- PDF 견적서 업로드 → 필드 자동 추출 → 검토 화면에서 확인/수정 → 확정 → CSV 내보내기
- 텍스트 기반 PDF 우선. 스캔본은 지원하되 정확도 목표에서는 제외.

**범위 밖**
- ERP 직접 연동 (CSV 업로드로 대체)
- 이메일 자동 수집 (수동 업로드로 시작, 2단계에서 검토)
- 발주서, 세금계산서 등 다른 문서 유형

## 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 양식이 너무 다양해서 정확도가 안 나옴 | 상위 20개 협력사 양식으로 먼저 검증, 나머지는 점진 확대 |
| 스캔본 품질 문제 | 1단계에서는 정확도 목표 제외, 검토 화면에서 원본 대조 가능하게 |
| LLM 비용 | 건당 비용 측정 후 월 예상 비용 산출, 고객에게 사전 공유 |
| 검토자가 AI 결과를 그냥 승인해버림 | 확신도 낮은 필드 강조 표시, 합계 검산 등 자동 경고 |
