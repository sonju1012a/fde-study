# 02. 요구사항 문서 (PRD)

## 사용자

- **검토자 (구매팀 대리)**: 견적서를 업로드하고, 추출 결과를 검토·수정·확정한다. 하루 15~25건 처리.
- **관리자 (구매팀장)**: 처리 현황과 정확도 지표를 본다. (이번 범위에서는 간단한 통계만)

## 핵심 사용자 흐름

1. 검토자가 견적서 PDF를 업로드한다 (여러 건 동시 가능).
2. 시스템이 각 PDF에서 필드를 추출하고, 상태를 "검토 대기"로 둔다.
3. 검토자가 목록에서 건을 열면, 왼쪽에 원본 PDF, 오른쪽에 추출된 필드가 나란히 보인다.
4. 확신도가 낮거나 검산이 안 맞는 필드는 강조 표시된다.
5. 검토자가 값을 수정하거나 그대로 승인하고 "확정"한다.
6. 확정된 건들을 CSV로 내보내 ERP에 업로드한다.

## 추출 대상 필드

### 헤더 정보
| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| 공급사명 | string | ✓ | |
| 사업자등록번호 | string | | 000-00-00000 형식으로 정규화 |
| 견적번호 | string | | 협력사가 부여한 번호 |
| 견적일자 | date | ✓ | YYYY-MM-DD로 정규화 |
| 유효기간 | date 또는 string | | "견적일로부터 30일" 같은 표현도 있음 |
| 담당자명 | string | | |
| 담당자 연락처 | string | | 전화 또는 이메일 |
| 납기 | string | | "발주 후 2주" 등 자유 형식 |
| 결제조건 | string | | |

### 품목 라인 (1건에 여러 개)
| 필드 | 타입 | 필수 |
|---|---|---|
| 품명 | string | ✓ |
| 규격 | string | |
| 수량 | number | ✓ |
| 단위 | string | |
| 단가 | number | ✓ |
| 금액 | number | ✓ |

### 합계
| 필드 | 타입 | 필수 | 비고 |
|---|---|---|---|
| 공급가액 | number | ✓ | 품목 금액 합과 일치해야 함 |
| 세액 | number | ✓ | 보통 공급가액의 10% |
| 합계 | number | ✓ | 공급가액 + 세액 |

## 기능 요구사항

- **F1. 업로드**: PDF 다중 업로드. 파일당 10MB 이하.
- **F2. 추출**: Claude API로 PDF를 직접 읽어 위 스키마대로 JSON 추출. 필드별 확신도 포함.
- **F3. 검산**: 품목 금액 = 수량 × 단가, 공급가액 = 품목 합, 합계 = 공급가액 + 세액을 자동 검사하고 불일치 시 경고.
- **F4. 검토 화면**: 원본과 추출 결과를 나란히 표시. 필드 인라인 수정. 수정 이력 저장.
- **F5. 확정 및 내보내기**: 확정 건을 ERP 업로드용 CSV로 내보내기.
- **F6. 목록/상태**: 검토 대기 / 확정 상태별 목록, 검색.
- **F7. 지표**: 건별 처리 시간, 필드별 수정 빈도 기록 (정확도 개선의 근거 데이터).

## 비기능 요구사항

- 추출 1건당 응답 60초 이내 (스트리밍으로 진행 표시).
- API 키 등 비밀은 서버에서만 사용. 클라이언트에 노출 금지.
- 실패한 추출은 재시도 가능하고, 원인(파싱 실패/API 오류)을 기록.
- 건당 LLM 비용을 로그에 남겨 월 비용 추정 가능하게.

## 평가 계획 (Phase 5에서 구체화)

- 샘플 견적서 30건 이상 + 사람이 작성한 정답 데이터로 평가셋 구성.
- 필드별 정확도(exact match, 숫자는 허용오차 0), 품목 라인 단위 정확도, 전체 건 단위 "수정 없이 통과" 비율.
- 프롬프트/모델 변경 시 평가셋을 다시 돌려 회귀 확인.

## 고객에게 확인이 필요한 열린 질문

FDE 연습용: 아래 질문을 "고객 역할"을 맡은 상대에게 직접 물어보고 답을 이 문서에 기록한다.

1. 유효기간이 "견적일로부터 N일"처럼 상대 표현이면 날짜로 계산해서 넣어야 하는가, 원문 그대로 두는가?
2. 외화(USD) 견적도 있는가? 있다면 환율 처리는?
3. 같은 협력사가 같은 견적을 수정해서 다시 보내는 경우, 중복은 어떻게 처리하는가?
4. ERP CSV 업로드 포맷의 정확한 컬럼 정의는? (샘플 파일 요청)
5. 검토자가 수정한 값과 AI가 뽑은 값이 다를 때, 그 기록을 누가 보는가? 감사(audit) 용도인가?
6. 스캔본 비율은 전체의 몇 %인가?
7. 한 PDF에 견적서가 여러 장 들어있는 경우가 있는가?

## 결정 사항 (2차 인터뷰 및 데이터 분석 후)

| 주제 | 결정 | 근거 |
|---|---|---|
| 자동 입력 범위 | 1차는 CSV 내보내기 + 품목 그리드 붙여넣기 텍스트. ERP 직접 입력은 2차 | ERP가 설치형이고 외부 계정 발급이 보안 승인 사항. 벤더 API 여부는 고객이 확인 중 |
| 붙여넣기 포맷 | 탭 구분, 열 순서 품명·규격·수량·단위·단가 | ERP 견적등록 화면의 "엑셀붙여넣기" 규격 |
| USD 견적 | 추출은 원문 통화(USD) 유지, 환율은 문서에 있을 때만 기록. 원화 환산은 CSV 바깥(구글 시트 GOOGLEFINANCE 수식)에서 | 고객은 발주일 환율로 환산해 입력. 환산 시점이 추출 시점과 달라 추출 단계에서 고정하면 틀린 값이 됨 |
| 환율 출처 | 1차: GOOGLEFINANCE 현재 환율(참고값). 검토자가 매매기준율로 덮어쓸 수 있음 | 고객이 Google Workspace 사용 중이라 추가 비용·연동 없음. 단 회계 기준인 서울외국환중개 매매기준율과 소폭 차이 가능 → 고객 확인 필요 |
| 유효기간 | 상대 표현("견적일로부터 30일")은 type=relative로 추출하고, CSV 변환 단계에서 견적일 + N일로 계산해 유효일자 컬럼에 넣음 | ERP는 날짜만 받음. 대리들이 지금 손으로 계산하는 규칙과 동일 |
| 정답 데이터 | ERP 입력값을 정답으로 쓰되, 입력 오류가 섞여 있을 수 있으므로 불일치 건은 PDF 원본으로 재확인 | 고객이 "사람이 넣은 거라 틀린 데가 있을 수 있다"고 명시 |
| 검산 | 수량×단가, 품목 합=공급가액, 부가세 10%, 합계를 코드로 검사해 경고 컬럼에 기록 | 발주 사고 방지가 고객의 진짜 목표. 모델이 아니라 코드가 보장해야 하는 부분 |
